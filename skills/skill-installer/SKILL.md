# 技能安装

目标：把技能目录放到**当前 Agent 客户端真正扫描的根目录**。

不同 Agent 产品的技能根目录互不相同，同一台机器上还可能并存多个 Agent。因此不要照着某个固定路径复制，而是先确定环境，再决定目标。

## 执行顺序

1. 确认当前 Agent 客户端
2. 确认操作系统
3. 确定技能根目录
4. 选择安装方式
5. 执行并验证

## 1. 确认当前 Agent 客户端

**你就是这个客户端。** 依据你能获得的运行时信息判断，不要猜：

- 哪个技能系统加载了本技能（本技能文件的来源目录本身就是证据）
- 可查询的运行时环境变量
- 会话提供的上下文

判定不出来时询问用户「你现在用的是哪个 Agent 客户端」，不要默认某个产品，也不要同时往多个根目录写。

## 2. 确认操作系统

用你所在平台的常规方式确认（如 `uname -s`、`$env:OS`、路径分隔符），不要用目录名或语言环境推断。

## 3. 确定技能根目录

### DeepSeek Harness（DSH）

按优先级扫描，同名时 rank 小的优先：

| Rank | 范围 | 路径 |
|---|---|---|
| 100 | 项目 | `<项目根>/.dsh/skills` |
| 200 | 项目 | `<项目根>/.agents/skills` |
| 400 | 用户 | `~/.dsh/skills` |
| 500 | 用户 | `~/.agents/skills` |

项目根是最近的含 `.git` 的祖先目录；没有 `.git` 时用当前工作目录。只识别直接子级：`<name>/SKILL.md` 或 `<name>.md`，嵌套的 `**/SKILL.md` 不扫描。

### Claude Code

| 范围 | 路径 |
|---|---|
| 个人（所有项目） | `~/.claude/skills/<name>/SKILL.md` |
| 项目 | `<项目根>/.claude/skills/<name>/SKILL.md` |

Claude Code **不扫描** `~/.agents/skills`。它会从启动目录起向上读各级 `.claude/skills/`，直到仓库根。

### 其他客户端

查阅该客户端的官方文档确认根目录。**不要猜测，也不要把别的产品的路径套用过来。**

## 4. 选择安装方式

| 方式 | 适用 | 取舍 |
|---|---|---|
| 软链接 | macOS、Linux；Windows 已开启开发者模式或以管理员运行 | `git pull` 后自动生效，不用重装 |
| 复制 | 全部平台，包括 Windows 默认状态 | 最稳，但每次更新需重新复制 |

Windows 创建符号链接默认需要开发者模式或管理员权限，**不要假设可用**。优先尝试链接，失败就回落复制，并告知用户所选方式。

## 5. 执行

用当前平台的工具，不要写跨平台的 shell 脚本去兼容所有系统——由你在执行时按平台选择命令：

- **macOS / Linux**：`ln -s <源目录> <目标>` 建立链接；或 `cp -R <源目录> <目标>` 复制
- **Windows（PowerShell）**：`Copy-Item -Recurse -Force <源> <目标>`；链接用 `New-Item -ItemType SymbolicLink`

## 安装前后的检查

**装之前**

- 目标位置已有同名技能时，先问用户是覆盖还是保留，不要直接覆盖
- 校验 `SKILL.md` 的 `name` 是 kebab-case（`^[a-z0-9]+(-[a-z0-9]+)*$`），且与目录名一致

**装之后**

逐个读回目标位置的 `SKILL.md`，确认能读到内容且 `name` 与预期一致。这一步不能省：DSH 等客户端对非法技能名是**静默丢弃**——不报错，只是技能不出现，很难排查。

## 完成

向用户报告：装到哪个根目录、用了链接还是复制、装了几项、哪些因重名被跳过。

链接方式要提醒一句：链接指向源目录，源目录移动或删除会导致技能失效。
